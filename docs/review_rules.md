## 1. Security (Highest Priority)

- **Secrets:** no hardcoded tokens/keys/passwords. `.env` is secrets only; behaviour belongs
  in `config.yaml`. No new `HERMES_*` env var for non-secret config.
- **Profile scope:** any code running outside a turn (boot probes, eviction, tickers,
  deferred callbacks, RPC methods, thread hops, child spawns) must bind the owning profile
  scope explicitly (HX002/HX004/HX005/HX012). Unbound `os.environ`/module-global reads are a
  silent default-profile leak.
- **Auth:** one session-token scheme for every REST route and WS endpoint. Never a second
  scheme; WS auth stays a query param.
- **Input boundaries:** unusable credentials/config/input are rejected where read, naming the
  problem. No silent no-ops.
- **Telemetry:** outbound telemetry requires an opt-in gate.
- **Disclosure:** `SECURITY.md` is the scope authority. A §3.1 finding is private only
  (Security Advisories / security@nousresearch.com) — flag, do not comment with detail.
- **Logs:** no passwords, tokens, API keys, client secrets.

## 2. Type Safety / Data Model

- TypeScript: `consistent-type-imports` with `prefer: type-imports`; no unused imports.
- `interface` for props and shared shapes; no threaded state across feature boundaries —
  feature-owned nanostores.
- Python: no runtime coercion of config values; validate at the boundary and fail loud.
  `py311` syntax floor under a 3.14 runtime.
- Schema/state fields used by guards (`_state.json`, `progress.md`) must keep the canonical
  names; scripts read them directly.

## 3. Framework Patterns

- **Hermes core:** facade + topical sibling layout. New behaviour goes in
  `<stem>_<topic>.py`, never a facade; siblings late-import the facade inside functions.
  No re-export shims.
- **Dashboard (`web/`):** the chat surface is the embedded real `hermes --tui` over
  `/api/pty`. Do not re-implement transcript/composer in React. Structured side panels are
  fine if their state stays independent of the PTY child. One router file per surface.
- **`dashboard` vs `serve`:** independent surfaces; `serve` is the headless desktop
  backend. Capability truth is `hermes_cli/web_server_surface.py`.
- **Dependencies:** exact pins for core PyPI, `<next_major` bounds for extras; git URLs and
  Actions pinned to a full SHA; `uv.lock`/`pnpm-lock.yaml` travel with the manifest; PM
  operations only, never raw pip/uv.
- **Skills:** `description` ≤ 60 chars, one sentence, period; frontmatter complete;
  `platforms:` audited against real imports; author credits the human first; test at
  `tests/skills/test_<skill>_skill.py`.
- **Plugins:** published plugin API only (`ctx`, `plugin_api.json`). No core patching, no
  new core→plugin import.

## 4. Code Quality

- **Size ratchet:** CC ≤ 20, function ≤ 300 lines, nesting ≤ 6, file ≤ 2,000 lines. Existing
  over-cap units may only shrink. `# noqa` does not waive a ratchet finding;
  `# health: allow <RULE> -- <why>` does.
- **No defensive clutter:** no `try/except: pass` around infallible code, no flags nobody
  sets, no dead code.
- **No hardcoded `~/.hermes`** — `get_hermes_home()` / `display_hermes_home()`.
- **No argv substring identity** — use the status/update helpers (HX003).
- **Python style:** ruff format (88 cols, double quotes, 4-space, auto line endings).
- **TS style:** `curly: all`, sorted imports/exports/JSX props (natural, asc), no unused
  imports; `src/app` routes, `src/store` atoms, `src/lib` pure helpers.
- **Docs travel with the change:** moving a symbol updates `website/docs`, `skills/`, and
  every `AGENTS.md` in the same PR. `AGENTS.md` stays inside its 12k/30k budget.
- Comments keep the WHY, not the WHAT.

## 5. Testing

- `scripts/run_tests.sh` only — never bare `pytest`; flags pass through
  (`scripts/run_tests.sh tests/agent/test_x.py -k test_y`).
- Placement mirrors the source tree; no issue numbers in filenames.
- No network, no `~/.hermes/` writes; fixtures serve local data.
- Host-differential behaviour uses one `@pytest.mark.platforms(...)` marker, tested on that
  host. No `sys.platform` patching, no bare `skipif`.
- No change-detector tests; no tests that read source text.
- Timing: bounds ≥ 2 s, event-based sync, no new non-zero sleeps (HX013).
- Python tests do not assert about JS manifests/sources — vitest owns those.
- Each fix carries 1–2 invariant tests, proven red on the base.

## 6. Review Exclusions (May Suppress Comments)

- Generated: `**/*.generated.ts` (e.g.
  `omp-ui/src/modes/rpc/gateway-contract.generated.ts`, emitted by
  `scripts/gen_gateway_contracts.py`), `**/generated/**`
- Vendored: `omp-ui/src/**` (only `OMP_OWNED` files in
  `scripts/code_health/config.py` are ours), `tools/eval_js_parser.ts` (acorn dist)
- Lockfiles: `uv.lock`, `pnpm-lock.yaml`, `flake.lock`, `package-lock.json`
- Build/deps: `node_modules/**`, `**/dist/**`, `**/build/**`, `**/.venv/**`, `venv/**`,
  `**/__pycache__/**`, `.pytest_cache/**`, `.ruff_cache/**`
- Specs: `.specs/**`
- Byte-identical upstream mirrors listed in `VENDORED.md` files
- Do not comment on unchanged lines merely because they violate a rule.

## 7. Review Output Guidelines

### Common Rules
- Prioritize high-impact issues; suppress minor style suggestions (the linters own style).
- Do not comment on existing code (unchanged lines) in principle.
- Do not assert without evidence (diff, rule reference, command output).
- Cite the rule: `coding-rules.md` § section, or the area `AGENTS.md`.

### Severity Classification
- **Critical (security/bugs/missing docs)**: must be addressed; not downgraded in a fix loop.
- **Improvement (quality/readability)**: recommended.
- **Minor (style)**: optional; only if no CI check covers it.

### Output by Use Case
- **CI review**: inline for high-confidence only (QUICK max 5, DEEP max 10); summary comment
  when the target line is ambiguous.
- **Review gate (spec-implement)**: detect critical/improvement issues and resolve via the
  fix loop; self-fix, do not post.
- **Second opinion (peer vendor)**: structured report to the parent session.

### Review Modes
- **QUICK**: high-impact only.
- **DEEP**: includes minor improvement suggestions.

## 8. Documentation Update Check — Severity: Critical

Documentation omissions are Critical findings; they are not downgraded in the fix loop.

### Step 1: Check Known Documentation Files
- `README.md` (+ `README.es.md`, `README.ur-pk.md`, `README.zh-CN.md`), `CONTRIBUTING.md`,
  `SECURITY.md`, `SOUL.md`
- `AGENTS.md` at root and every area (`agent/`, `gateway/`, `tools/`, `plugins/`,
  `hermes_cli/`, `tui_gateway/`, `web/`, `apps/desktop/`, `skills/`, `cron/`, `tests/`,
  `pm/`, `hermes_platform/`, `hermes_cache/`, `agent/prompts/`)
- `docs/`, `website/docs/`, `plugin-catalog/README.md`
- `cli-config.yaml.example`, `config.yaml` reference docs

### Step 2: Scan for Additional Documentation
```bash
find . -maxdepth 6 \( -name "*.md" -o -name "*.mdx" \) \
  -not -path "*/node_modules/*" -not -path "*/.git/*" -not -path "*/dist/*" \
  -not -path "*/build/*" -not -path "*/.venv/*" -not -path "*/.specs/*" 2>/dev/null

find . -maxdepth 4 -type d \( -name docs -o -name documentation -o -name wiki \) \
  -not -path "*/node_modules/*" -not -path "*/.venv/*" 2>/dev/null
```

`scripts/ci/check_docs_drift.py` and the plugin-catalog mirror test already enforce some of
this; a change that trips them is a documentation omission, not a flake.

### Step 3: Classify and Check

| Category | Update required when |
|---|---|
| README / install docs | Feature added, install or setup steps changed |
| `AGENTS.md` | Architecture, invariants, routing, or commands changed |
| `website/docs/**` | User-facing behaviour, CLI flags, config keys, plugin API changed |
| `plugin-catalog/README.md` | Admission rules changed (mirror must match docs) |
| Config reference | New or changed `config.yaml` key |
| `docs/adr/**` | A significant design decision was made |
| `skills/**` | A skill's procedure, prerequisites, or scripts changed |

### Step 4: Report
Flag each documentation file that should be updated but is absent from the changeset.
