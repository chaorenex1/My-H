## Testing Standards

### [MUST] Canonical runner
- Run tests with `scripts/run_tests.sh`, never bare `pytest`. CI parity: credentials
  unset, `TZ=UTC`, `LANG=C.UTF-8`, `HERMES_HOME` redirected to a temp dir, per-file
  subprocess isolation via `scripts/run_tests_parallel.py`.
- Source: `tests/AGENTS.md` § Running tests

### [MUST] Placement mirrors the source tree
- A test lives in `tests/<top-level source dir>/` (`tests/hermes_cli/`, `tests/agent/`,
  `tests/hermes_state/`, `tests/gateway/relay/`, ...). Only root-module tests sit
  directly in `tests/`. No issue numbers in filenames — cite the issue in the module
  docstring.
- Source: `tests/AGENTS.md` § Placement

### [MUST] Tests never reach the network
- `tests/conftest.py` fences every non-loopback lookup for the whole pytest process.
  Serve what the test needs from a fixture (`127.0.0.1` server, stubbed transport,
  seeded cache, `public_dns`). Only `@pytest.mark.live` (secrets-gated) and
  `@pytest.mark.allow_network` (PM toolchain downloads) open it.
- Source: `tests/AGENTS.md` § Tests never reach the network

### [MUST] Tests never write to `~/.hermes/`
- Rely on the autouse `_isolate_hermes_home` fixture; never hardcode `~/.hermes/`.
  Profile tests must mock `Path.home()` **and** set `HERMES_HOME`.
- Source: `tests/AGENTS.md` § Tests must not write to `~/.hermes/`

### [MUST] Host-specific behaviour is tested on that host
- Use `@pytest.mark.platforms(...)` — one marker per test, multiple specs in one
  marker. Never patch `sys.platform`, never set a module-level `IS_WINDOWS` flag to
  fake a host, never use a bare `skipif(sys.platform ...)` (the OS lane never imports
  it, so it runs nowhere).
- Source: `tests/AGENTS.md` § Don't fake the host OS

### [MUST] No change-detector tests
- Do not assert on data expected to change (model catalogs, `_config_version`,
  enumeration counts). Assert the relationship between two pieces of data instead.
- Source: `tests/AGENTS.md` § Don't write change-detector tests

### [MUST] Never read source code in tests
- A test that reads `.py`/`.ts`/`.tsx` text tests source shape, not behaviour. Extract
  the logic into a pure/DI-testable function and call it.
- Source: `tests/AGENTS.md` § Never read source code in tests

### [MUST] Timing and flake policy
- Wall-clock bounds ≥ 2 s, event-based sync (`tests.waiting.wait_until` /
  `async_wait_until`), no new non-zero `time.sleep`/`asyncio.sleep` in tests (HX013).
  A pass-on-retry is `⚠ FLAKY` — a bug to fix, not noise.
- Source: `tests/AGENTS.md` § Flake policy

### [MUST] Cross-language test lanes
- Python tests must not assert about `package.json`, `pnpm-lock.yaml`, `tsconfig.json`,
  or `.ts/.tsx/.js/.mjs/.cjs` sources: those files are not classified into the Python
  lane and the test would be green on PR, red on `main`. Such assertions belong in the
  vitest suite.
- Source: `tests/AGENTS.md` § Placement (CI lanes), `web/AGENTS.md` § Rules

### [MUST] One or two invariant tests per fix
- Prove the new test red on the base revision; behaviour contracts only.
- Source: `AGENTS.md` § Rules that apply everywhere

## Code Quality

### [MUST] `python scripts/check` before push
- CI runs the same command: workflow guards, `ruff`, and the code-health ratchet, plus
  the case-collision, lazy-deps, profile-archive and blob-size guards. Install it with
  `python scripts/check --install-hook pre-push` (re-run after pulling).
- Source: `scripts/check`, `CONTRIBUTING.md` § Code health ratchet

### [MUST] Per-unit size ratchet
- Cyclomatic complexity ≤ 20, function ≤ 300 lines, nesting ≤ 6, file ≤ 2,000 lines.
  Units already over their target may only go down. New behaviour goes in a topical
  sibling, never a facade. `# noqa` does not waive a ratchet finding; use
  `# health: allow <RULE> -- <why>`.
- Source: `scripts/code_health/config.py`, `AGENTS.md` § Facade + siblings layout

### [MUST] Facade + topical siblings
- `hermes_state.py`, `run_agent.py`, `cli.py`, `gateway/run.py`, `tools/mcp_tool.py`,
  `hermes_cli/*` are facades: public entry points and imported names only. Behaviour
  lives in `<stem>_<topic>.py`. Siblings late-import the facade inside functions; never a
  module-level cycle. No re-export shims for internal moves — fix the docs in the same
  PR instead (`website/docs`, `skills/`, every `AGENTS.md`).
- Source: `AGENTS.md` § Facade + siblings layout

### [MUST] No defensive clutter
- No wrappers or `try/except: pass` around code that cannot fail, no flags nobody sets,
  no dead code wired in without E2E proof.
- Source: `AGENTS.md` § Rules that apply everywhere

### [MUST] No hardcoded `~/.hermes`
- `get_hermes_home()` for paths, `display_hermes_home()` for text (HX001).
  `_get_profiles_root()` is HOME-anchored on purpose.
- Source: `AGENTS.md` § Rules that apply everywhere

### [MUST] Identity comes from structure, not argv
- Never infer process identity from argv substrings; use
  `gateway.status.looks_like_gateway_command_line` /
  `hermes_cli.update_cmd._hermes_holder_subcommand` (HX003).
- Source: `AGENTS.md` § Rules that apply everywhere

### [MUST] Dependency pinning
- PyPI: exact `==X.Y.Z` for core; extras carry upper bounds. Git URLs: 40-char commit
  SHA. GitHub Actions: SHA + `# vN` comment. CI-only Python requirements: `==exact`.
  After editing `pyproject.toml`: `hermes pm lock`, re-source `./activate`, commit
  `uv.lock` with it. Never mutate a Hermes environment with raw pip/uv.
- Release-age gate: 3 days for PyPI, 14 days (`minimumReleaseAge`) for pnpm.
- Source: `pm/AGENTS.md`, `pyproject.toml`

### [MUST] No new core/plugin crossings
- Core never imports a specific bundled plugin; plugins use only the published plugin
  API (`hermes_cli/data/plugin_api.json`, `ctx`). `scripts/boundary_lint.py` fails CI
  on new crossings.
- Source: `AGENTS.md`, `plugins/AGENTS.md`

### [MUST] Python style
- `ruff format` semantics: wraps at 88 columns, 4-space indent, double quotes,
  automatic line endings. Line length is **not** lint-enforced (E501 is not selected) —
  `CONTRIBUTING.md` § Code Style allows practical exceptions, but keep new code inside
  the formatter's wrap. Lint target is `py311` — syntax must stay valid on the 3.11 floor
  even though runtime dependencies require 3.14. `max-complexity = 20`. Banned imports:
  `pm.uv` and friends (use PM's semantic operations).
- Source: `ruff.toml`

### [MUST] TypeScript style
- `@typescript-eslint/consistent-type-imports` (`type-imports`), `curly: all`,
  `unused-imports/no-unused-imports`. `perfectionist` sorts imports, exports,
  named imports/exports and JSX props ascending, natural order. React hooks rules are
  errors; `exhaustive-deps` is a warning.
- Layout: `src/app` routes, `src/store` feature-owned nanostores, `src/lib` pure
  helpers; thin route roots, narrow hooks, colocated action modules; no threaded state.
- Source: `eslint.config.shared.mjs`, `AGENTS.md` § TypeScript

### [MUST] Shared contracts
- `interface` for props and shared shapes; table-driven dispatch over condition
  ladders.
- Source: `AGENTS.md` § TypeScript

### [MUST] Skill authoring standards
- `SKILL.md` frontmatter carries `name`, `description`, `version`, `author`, `license`,
  `platforms`, and `metadata.hermes.*` (tags, category, related_skills, config).
- `description` ≤ 60 chars, one sentence, ends with a period, no marketing words, does
  not repeat the skill or category name.
- Prose names native Hermes tools in backticks (`terminal`, `read_file`, `patch`,
  `search_files`, `browser_exec`, `delegate_task`), not shell utilities.
- Modern section order; `platforms:` gating audited against real imports.
- Tests at `tests/skills/test_<skill>_skill.py`.
- Source: `skills/AGENTS.md` § Authoring standards

## Error Handling

### [MUST] Fail loud at integration boundaries
- When a configuration value, credential, or user input is unusable (placeholder token,
  empty required field, out-of-range number), reject it where it is read and name the
  problem. Never a silent no-op. Each boundary validates its own values in place — there
  is intentionally no shared `fail_loud` helper.
- A silent default is acceptable only where it is a deliberate product choice documented
  in the config reference.
- Source: `CONTRIBUTING.md` § Fail loud at integration boundaries

### [MUST] No swallowed errors
- Do not wrap fallible code in `try/except: pass`. Errors surface with context; a
  deliberate fallback states why in a comment.
- Source: `AGENTS.md` § No defensive clutter

## Security

### [MUST] No hardcoded secrets
- `~/.hermes/.env` is secrets only; behaviour goes in `config.yaml`. Never add a new
  `HERMES_*` env var for non-secret config.
- Source: `AGENTS.md` § Rejected even when well-built, § User state

### [MUST] No telemetry without an opt-in gate
- Outbound telemetry requires explicit consent.
- Source: `AGENTS.md` § Rejected even when well-built

### [MUST] Profile scope is explicit outside a turn
- Boot probes, eviction, tickers, deferred callbacks, RPC methods, thread hops and
  child spawns bind the owning profile scope explicitly (HX002/HX004/HX005/HX012,
  PS-P05/P06). `os.environ`, module globals and import-time values hold the launch
  profile's value — an unbound read is a silent default-profile leak.
- Source: `AGENTS.md` § One process serves many profiles

### [MUST] Disclosure scope
- `SECURITY.md` is the scope authority. A §3.1 finding goes private (GitHub Security
  Advisories or security@nousresearch.com), never into a public issue, PR, commit or
  comment. §3.2 hardening is ordinary public work. Name the §2 boundary crossed, with a
  repro on `main`.
- Source: `SECURITY.md`, `AGENTS.md` § Security

### [MUST] One auth scheme per surface
- Every REST route and WebSocket endpoint uses the same session token
  (`_SESSION_TOKEN`); never a second scheme. WS auth travels as a query param because
  browsers cannot set `Authorization` on upgrade.
- Source: `web/AGENTS.md` § Rules

### [MUST] Validate input at system boundaries
- Validate before use, fail fast with a clear message, never trust external data.
- Source: `CONTRIBUTING.md` § Fail loud, `AGENTS.md` § Input validation

### [SHOULD] Diagnostic output carries no secrets
- Do not log passwords, tokens, API keys, or client secrets; error paths include
  context (operation, input summary) without payloads.
- Source: `AGENTS.md` § Error handling, `SECURITY.md`

### [MUST] Vendored trees stay byte-identical
- `omp-ui/src` is a vendored upstream snapshot (see `omp-ui/src/VENDORED.md`) and is
  excluded from `ruff`/eslint rewrites; refresh it with `omp-ui/scripts/sync-upstream.py`
  only. Treat `node_modules/`, `dist/`, `build/`, `*.generated.ts` as generated output.
- Source: `ruff.toml`, `eslint.config.shared.mjs`, `scripts/code_health/config.py`

## Git

### [MUST] Conventional Commits
- Format: `<type>(<scope>): <description>`. Types: `fix`, `feat`, `docs`, `test`,
  `refactor`, `chore`. Scopes: `cli`, `gateway`, `tools`, `skills`, `agent`, `install`,
  `security`, ...
- Language: English.
- Source: `CONTRIBUTING.md` § Commit messages

### [MUST] Rebase before merging
- Rebase onto `main` first. A squash from a stale branch silently reverts newer fixes.
- Source: `AGENTS.md` § Rules that apply everywhere

### [MUST] Lockfile travels with the manifest
- Commit `pyproject.toml` and `uv.lock` together; JS manifests travel with
  `pnpm-lock.yaml`.
- Source: `pm/AGENTS.md`

### [SHOULD] Atomic commits
- One logical change per commit; keep unrelated refactors out.
- Source: `CONTRIBUTING.md` § Pull requests

### [SHOULD] PR body carries a test plan
- State how it was tested, on which platforms, and any related issue.
- Source: `.github/PULL_REQUEST_TEMPLATE.md`, `CONTRIBUTING.md`
